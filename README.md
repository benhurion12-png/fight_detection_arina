# KU Fight detection

Веб-приложение для распознавания драк на видео и с веб-камеры. Next.js показывает трансляцию, а серверный ONNX Runtime анализирует последние 8 кадров. Светлая и тёмная темы, регулируемый порог, пауза и таблица результатов.

**Модель включена в репозиторий. Python, PaddlePaddle и исходный PaddleDetection для запуска не нужны.**

## Установка и запуск

Требуется **Node.js 22 LTS**, npm и современный браузер (Chrome или Edge для проверенного сценария).

Скачайте репозиторий через Code → Download ZIP и распакуйте, либо клонируйте:

```sh
git clone https://github.com/benhurion12-png/fight_detection_arina.git
cd fight_detection_arina
```

В терминале из папки с `package.json`:

```sh
npm ci
npm run build
npm start
```

Откройте **http://localhost:3000**. Выберите видео или нажмите «Включить веб-камеру». Воспроизведение и анализ запускаются автоматически. Для разработки используется `npm run dev`.

Веб-камере требуется разрешение браузера и безопасный адрес: `localhost` или HTTPS. При доступе с другого компьютера по обычному HTTP камера может быть недоступна.

## Сервер и ускорение

- В Windows по умолчанию используется GPU через DirectML; если создание GPU-сессии не удалось, используется CPU.
- На Linux и macOS по умолчанию CPU. GPU в этих окружениях отдельно не настраивался и не проверялся.
- При запуске сервер загружает и прогревает модель. Первый прогрев GPU может занимать около минуты. Видео может проигрываться в это время; оценки начнут поступать после готовности модели. Последующие запросы используют сессию в памяти.
- Для принудительного CPU скопируйте `.env.example` в `.env.local` и добавьте `FIGHT_BACKEND=cpu`, затем перезапустите сервер.
- Для другого порта: `npm start -- --port 3001`.

Нужен долгоживущий **Node.js сервер**. GitHub хранит исходники; GitHub Pages не запускает этот сервер. Для удалённого развёртывания установите проект на машине/VPS с Node.js и запускайте те же команды. Сам проект не содержит авторизации и предназначен для локального либо доверенного доступа.

## Обработка видео

При 30 FPS первая оценка требует примерно двух секунд накопления кадров плюс время обработки. Затем анализируются перекрывающиеся окна. Видео не останавливается в ожидании ответа. Если сервер занят, старые окна не накапливаются: следующий запрос берёт свежие кадры.

Кадры передаются серверу, нормализуются и анализируются в отдельном Node.js worker thread. Аудио не запрашивается, видео и кадры не сохраняются на диск. Один запрос содержит 8 кадров RGBA 320 × 320, около 3.3 МБ; пропускная способность сети влияет на задержку. Прототип рассчитан преимущественно на один активный поток, несколько клиентов делят одну модель.

Оценка относится ко всему окну; модель не определяет участников и не рисует рамки. Начальный порог 70% не является результатом калибровки на ваших данных.

## Файлы

```text
app/                       Интерфейс и HTTP API
server/                    Серверная модель и worker thread
public/models/fight.onnx    Готовая модель ppTSM Fight
public/models/manifest.json Форма входа и результаты проверки экспорта
instrumentation.ts         Автоматический запуск модели
next.config.ts
package.json
package-lock.json
```

Модель запускается из `public/models`; запускайте npm-команды из корня проекта. При копировании на другой сервер нужны исходники `app`, `server`, `instrumentation.ts`, конфигурация, оба файла модели и npm-зависимости. Папки `node_modules` и `.next` генерируются при установке/сборке и не коммитятся.

## Модель и проверка

Использована ppTSM Fight из PaddleDetection / PP-Human, преобразованная в ONNX. Модель имеет вход `[1,8,3,320,320]`; класс 1 — драка. Экспорт проверен сравнением Paddle и ONNX Runtime на одинаковых входных тензорах; результаты находятся в manifest. Сведения об исходном проекте — в `THIRD_PARTY.md`.

Проверенный основной сценарий: Windows, Node.js 22, Chrome, GPU / DirectML. На исходной машине серверный инференс занимал примерно 0.52–0.63 секунды на окно; CPU около 4–5 секунд. Это замеры производительности на конкретном компьютере, а не гарантия скорости или точности. Веб-камера в автоматической проверке заменялась виртуальным источником.

## Публикация на GitHub

Создайте пустой репозиторий `ku-fight-detection` на GitHub, без автоматически созданного README. Из этой папки выполните:

```sh
git init -b main
git add .
git status
git commit -m "Initial KU Fight detection app and model"
git remote add origin https://github.com/benhurion12-png/fight_detection_arina.git
git push -u origin main
```

Перед коммитом проверьте, что присутствуют `public/models/fight.onnx` и `manifest.json`, а `node_modules` и `.next` отсутствуют в списке.

ONNX-файл занимает 94 418 517 байт, около 90 МиБ: меньше лимита GitHub 100 МиБ на файл. Загрузка выполняется через Git; браузерная загрузка ограничена 25 МиБ. GitHub может показать предупреждение о большом файле. При регулярной замене больших весов лучше перейти на Git LFS или GitHub Releases.
